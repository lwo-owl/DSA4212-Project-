# Geometry, noise and evaluation allocation in black-box optimisation

DSA4212 project comparing Bayesian optimisation and CMA-ES under fixed objective-call budgets. The experiments separate the quality of points visited from the quality of the final recommendation.

## Repository contents

- **noisy_optimisation_master_shortlist.ipynb** is the single entry point. Its source cells generate the Python experiment scripts.
- **report/** contains the complete LaTeX source, bibliography, figures and the script for the report's paired analysis.
- **results/optimisation_results_full.zip** holds the 24 full Stage C seed blocks, the experiment source snapshot, settings and summaries.
- **results/shortlist/** holds the saved verification analysis. Its CSVs and plot were generated from the Stage C archive.

The objectives, instance settings and Gaussian observations are generated in the notebook. The two supporting BBOB functions are supplied by `coco-experiment`. There is no external dataset to download.

## Environment

Use a fresh Python 3.12 or 3.13 kernel in Colab or Jupyter. The saved Stage C experiment used Python 3.13.18 and the saved shortlist analysis used Python 3.12.14. The first notebook cell installs the exact scientific packages listed in `requirements.txt`. For a local environment, install those dependencies and Jupyter with:

```sh
python -m pip install -r requirements.txt jupyter
python -m jupyter notebook
```

Use the repository root as the notebook's working directory. In Colab, open the notebook and upload the Stage C ZIP to `/content`, then set `SHORTLIST_ARCHIVE = Path("/content/optimisation_results_full.zip")`.

## Reproduce the results

**Fast check using saved histories.** Run all cells with the default `PROFILE = "full"` and `RUN_MODE = "shortlist"`. The local configuration reads the bundled Stage C archive. It regenerates the cross-valley oracle counts, fixed-budget verification comparisons and plot without running a search.

**Regenerate the main experiments.** Set `PROFILE = "full"`, `RUN_MODE = "report"`, and `INCLUDE_SUPPORTING_TRANSFER = True`, then run all cells. This runs the main Stage A, B and C experiments, including the fresh Stage C and shortlist follow-up. For the earlier transfer result cited in the report, run `RUN_MODE = "custom"` and `CUSTOM_STAGES = ["transfer_original"]`. Use `RUN_MODE = "everything"` to include the development stages too. Full searches are computationally intensive. The smoke profile is for checking execution with smaller seed sets.

| Earlier Stage C fixed and adaptive allocations | `stage_c_fixed/full/paired_policy_effects.csv`, `stage_c_dynamic/full/paired_policy_effects.csv`, `stage_c_dynamic/full/paired_shortlist_effects.csv` |

| Shared-history ablation and supporting transfer | `stage_c_mechanisms/full/recommendation_ratios.csv`, `stage_c_mechanisms/full/paired_run_differences.csv`, `stage_c_mechanisms/full/prefix_diagnostics.csv`, `transfer_original/full/transfer_table.csv` |
| Shortlist follow-up | `shortlist/full/cross_valley_oracle.csv`, `shortlist/full/verification_summary.csv`, `shortlist/full/verification_paired_effects.csv` |

Paths are relative to the configured `RESULTS_ROOT`. Full Stage A, Stage B and earlier Stage C results are regenerated by the notebook. The bundled archives provide the saved full results for the shared-history experiment and shortlist follow-up.

To recompute the report's complete-block checks and cross-function bootstrap intervals, extract `results/optimisation_results_full.zip` into a separate folder and run:

```sh
python report/analyse_report.py PATH_TO_EXTRACTED_FOLDER/results/stage_c_mechanisms/full
```

The script uses its own fixed bootstrap seed, so the interval endpoints may differ slightly from the notebook's summaries.

## Build the report

Set the project GitHub URL in `report/main.tex`. Upload the contents of `report/` to Overleaf and select `main.tex` as the main document, or run `latexmk -pdf main.tex` from that directory. The bibliography uses BibTeX. Use the compiled PDF and the matching repository URL for the Canvas submission.
